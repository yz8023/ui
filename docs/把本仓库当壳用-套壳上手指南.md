# 把本仓库当壳用（套壳上手指南）

> 适用场景：你**不是**要把某个功能抄进已有项目，而是要把本仓库整体变成你自己的 App。
> 要抄单个功能请走 `docs/00-新人入口-先读这个.md` 的路线 B（按 F 编号 + `docs/功能逐项手册.md`）。
>
> 本指南存在的原因：仓库此前的文档 90% 篇幅在教「抄单功能」，「整壳复制」只有三行，
> 导致套壳的人自己摸索删改顺序，改到编译不过。下面把每一步写死。

## 0. 先认清这个壳的构成

`android/` 共约 14000 行 Kotlin，分两类：

| 类别 | 位置 | 行数 | 套壳时怎么处理 |
|---|---|---|---|
| **壳与视觉基建**（要留） | `ui/theme/`(1615)、`ui/components/`(2446)、`ui/motion/`(648)、`ui/navigation/`(490)、`ui/features/` 里的 `AppIconSwitcher`/`SystemWallpaper`/`WallpaperStore`/`PermissionToolkit` | ≈ 7900 | 保留，只改包名与文案 |
| **演示与素材目录**（要删） | `ui/features/ui2/`(10 文件)、`ui/features/adminquery/`(2)、`ui/features/overlayterms/`(3)、`ui/screens/` 里的 `Ui2Gallery.kt`、`AdminQueryScreen.kt`、`OverlayTermsScreen.kt`、`MaterialBrowser.kt`、`ComponentsScreen.kt`、`MotionScreen.kt`、`HomeScreen.kt` 的演示段 | ≈ 6100 | 按第 3 节顺序删 |

仓库根的 `素材库/`、`docs/`、`prompts/`、`web-preview/`、`preview/` 是**给抄功能的人看的文档与镜像**，
你的 App 不需要它们：确认不再回抄功能后可整体删除（删了以后 `scripts/check-template.py` 会失败，
该脚本是给模板维护者用的，一并删掉即可；CI 不依赖它）。

## 1. 三步起手

```bash
# ① 用 GitHub 页面右上角「Use this template」生成你自己的仓库（本仓库已开启模板开关）
#    —— 这样得到的仓库不带本项目的提交历史，最干净
# ② 克隆你的新仓库
git clone https://github.com/<你的账号>/<你的项目>.git MyApp && cd MyApp
# ③ 用 Android Studio 打开根目录（不是 android/），等 Gradle 同步
```

环境门槛：**JDK 17**、`compileSdk 36`、Gradle 8.11.1（用仓库自带 wrapper）、
真机/模拟器 **Android 12（API 31）以上**才能看到真 backdrop 玻璃效果（低版本自动降级，不崩）。

命令行构建：

```bash
cd android && ./gradlew :app:assembleDebug     # 产物 android/app/build/outputs/apk/debug/
```

## 2. 配置项对照表（改这 8 处就换完身份）

| # | 配置项 | 文件 | 改什么 |
|---|---|---|---|
| 1 | 命名空间 | `android/app/build.gradle.kts` 第 8 行 | `namespace = "com.monkeycode.liquidui"` → 你的包名 |
| 2 | 应用 ID | 同上 第 12 行 | `applicationId = "com.monkeycode.liquidui"` → 你的包名 |
| 3 | 版本 | 同上 第 15–16 行 | `versionCode` / `versionName` |
| 4 | 应用名 | `android/app/src/main/res/values/strings.xml` | `app_name`（当前是「Android 素材库示例」） |
| 5 | 全部 `.kt` 的 package/import | `android/app/src/main/java/com/monkeycode/liquidui/**` | 用 Android Studio 的 Refactor → Rename Package 一次性改；改完核对 `AndroidManifest.xml` 里的 `.MainActivity`、`.icon.Default/.icon.Galaxy/.icon.Coral` 三个 alias 仍指向正确类 |
| 6 | 源码目录路径 | `android/app/src/main/java/com/monkeycode/liquidui/` | 目录本身要跟着包名移动（`com/你的/包名/`），Studio 的重命名会做，手工改别漏 |
| 7 | 主题名 | `android/app/src/main/res/values/themes.xml` | `Theme.LiquidUI` 可保留，也可改成你的（Manifest 第 33 行同步） |
| 8 | 页面文案 | `android/app/src/main/res/values/strings.xml`（现 **1522 条**）：`nav_*` 底栏与页面标题、`common_*` 跨页共用（取消/确认/全部/提示词…）、`<页面 slug>_<角色>_<序号>` 各页专属文案、模型级标签（`palette_*`／`wallpaper_mode_*`／`window_class_*`／`onboarding_feature_*`／`feature_category_*`）、目录条目文案（`ui2_*`／`tk_*`／`ot_*`／`aq_*`：名字/摘要/参数/提示词与分类键文案）、页面级顶层数据（`info_credit_*` 开源致谢／`home_material_*` 与 `home_principle_*` 首页／`pv_motion_tool_recipe_*` 与 `pv_motion_tool_spec_*` 动效表／`pv_video_popup_*` 弹窗型别／`tk_demo_md_*` Markdown 示例） | 改品牌与页面文字**只改这一个 XML**，不用碰 Kotlin；命名约定与 slug 表见 `scripts/externalize-strings.py` 头部 |

> 关于 #8：文案外置**正在分批推进**，当前进度按字面量上下文分类（工具：`scripts/kt_scan.py`，
> 分类只有一份口径 `collect()`；复核闸门 `scripts/probe-i18n.py`）：
>
> | 类 | 含义 | 状态 |
> |---|---|---|
> | A/C1 | `@Composable` 函数体内与默认参数（含 `ui2/previews/` 演示页） | ✅ 能直接换的都换了：`stringResource` 调用点 823 个 |
> | B/C2 | 普通函数体内与默认参数（无组合上下文） | 🔶 部分完成：宿主带 Context 的改 `context.getString`（136 个调用点），没有 Context 的上提到调用点外存 val（42 处）；剩 **145 条**要么给函数加 Context 参数、要么改数据模型 |
> | D | 含 `${}`/`$name` 插值 | 🔶 阶段 4 已做 98 条 → `%1$s` 位置化格式参数 + `stringResource(id, arg)`；5d-1 又顺手做掉 1 条（`"$active（底部形态）"` → 格式资源 `pv_video_bottom_form_title`）；剩 **78 条**（阶段 4 当时按跳过原因分的四类：给状态变量赋文案约 45、非组合函数体且无 Context 约 23、表达式含嵌套字符串约 10、顶层 1；5d-1 消掉的那条实参是委托可空状态，本来不在这四类里） |
> | C3 | 顶层属性 / data class / enum 字段 | 🔶 5a 改了 5 个 enum/小数据类（27 条）；5b 改了 UI2 目录 77 条素材（322 条，含 46 条多行提示词）；5c 改了 `ToolkitSpec`／`OverlayTermsSpec`／`AdminQuerySpec` 的 21 条条目（180 条）；5d-1 改了 `PreviewMotionTools` 的 `Recipes`(20)+`Specs`(25×2)、`PreviewVideoLabs` 的 `PopupTypes`(10)、`ToolkitDemo` 三段 Markdown 示例（84 条，另删 4 条因此变成孤儿的资源）；5d-2 改了开源致谢 13 条(×4 字段)、首页特色素材 5 条与设计原则 4 条、权限卡 `deniedHint` 默认值（74 条）。做法统一：显示文案字段 → `@StringRes Int`，`category` 这种**既是文案又是筛选键**的拆成「稳定英文键 + `XxxCategoryLabels` 查表」，`id`／`slug`／`en`／`difficulty` 不动。剩 **33 条**：`AdminQuerySpec` 的模拟数据集 29 条（= 阶段 5e，最后一批）+ 4 条 Legacy `@Deprecated` 别名里的注解消息（**永久留在代码里**，注解参数要编译期常量，本来也不能用资源） |
>
> 剩余 **416 条**仍在 Kotlin 里，所以套壳时**不要以为改完 strings.xml 就没中文了**：
> 全局搜一遍中文字符再交付。
>
> 剩下的都不是「换个 API」能解决的：A 类剩的 160 条和 D 类剩的 78 条里有一大批是**给状态变量赋文案**
> 或**参与 `==` 比较 / 当 when 分支 / 当 map 键**——数据侧仍是硬编码中文，只把显示侧外置
> 会造成换语言即失配，正解是把判定依据从文案改成 id/枚举，得连数据模型一起动。
>
> 这条不是理论风险，仓库里真出现过：`PreviewVideoLabs.PreviewX01` 的 `when (active)` 一度是半迁移状态——
> 10 个分支里 5 个拿 `stringResource(...)`（随语言变）去比 `active`，而 `active` 来自硬编码中文的
> `PopupTypes`；另外 5 个分支还是硬编码中文。它当时能跑，纯粹因为**只有一种语言**。5d-1 已把它改成
> 「稳定英文键 to `@StringRes`」：键参与分派与状态，文案只用于显示。
> **规则：`when` 分支的比较操作数一律不许用 `stringResource`。**
>
> **摘素材的新注意事项**：`素材库/*/代码/` 里的 Demo 镜像现在会 `import com.monkeycode.liquidui.R`
> 并引用 `R.string.*`。只复制 `.kt` 不复制对应 strings 条目会编译不过——复制时把
> `strings.xml` 里同名分组（XML 里按源文件分了 `<!-- ===== 路径 ===== -->` 段）一并带走。

## 3. 删演示内容（按这个顺序，每步都能编译）

**顺序不能乱**：`AppRoot.kt` 与 `Screen.kt` 是接线中枢，先摘接线再删文件，否则中间状态编译不过。

1. **摘素材库分区**：`ui/navigation/AppRoot.kt` 里 `Screen.Gallery -> MaterialBrowser { ... }` 整段删掉；
   同文件 `TemplatePage` 的 `when` 里对应分支一并删。
2. **摘枚举项**：`ui/navigation/Screen.kt` 删 `Gallery`（以及你不要的 `Components` / `Motion`）；
   底栏 `screens` 列表会自动跟着变（它读 `Screen.entries`）。
3. **删目录/文件**：
   - `ui/features/ui2/`、`ui/features/adminquery/`、`ui/features/overlayterms/` 整个目录
   - `ui/screens/Ui2Gallery.kt`、`AdminQueryScreen.kt`、`OverlayTermsScreen.kt`、`MaterialBrowser.kt`
   - 不要组件展示页就删 `ui/screens/ComponentsScreen.kt`；不要动效展示页就删 `ui/screens/MotionScreen.kt`
     （注意：`ui/motion/` 是动效**基建**，被玻璃底栏等依赖，**不要删**；只删展示页）
4. **改首页**：`ui/screens/HomeScreen.kt` 里指向素材/组件/动效的入口按钮删掉或换成你的业务入口。
5. **改设置页**：`ui/screens/SettingsScreen.kt` 删掉你不要的项（壁纸、图标切换、主题导入导出、
   测试通知、重看引导）；每删一项要同时删它对应的 state 字段与 `AppSettingsState.kt` 里的持久化键，
   否则留着无用键（不报错但脏）。
6. **引导页**：要留就改 `ui/screens/WelcomeGuideScreen.kt` 的文案与卡片（`FreeNoticeCard`/`DisclaimerCard`/`OpenSourceRepoCard`）；
   不要留就删该文件 + `MainActivity.kt` 里的 `WelcomeGuideScreen(onFinish = settings::completeOnboarding)` 分支
   + `AppSettingsState.kt` 的 `resetOnboarding()`/`completeOnboarding()` 与对应键。
7. **权限页**：`ui/features/PermissionToolkit.kt` 与权限说明页保留与否，取决于你的 App 是否要
   「所有文件访问」（只有用系统壁纸功能才需要，见下条）。
8. **壁纸功能**：不用网络/系统壁纸就删 `ui/features/SystemWallpaper.kt`、`WallpaperStore.kt`、
   `ui/screens/WallpaperSettings.kt`，并从 `AndroidManifest.xml` 删掉 `INTERNET`、
   `READ_EXTERNAL_STORAGE`、`MANAGE_EXTERNAL_STORAGE` 三条权限（**只留你真正用的**，
   `MANAGE_EXTERNAL_STORAGE` 上架审核会问，别白送）。
9. **图标切换**：不用就删 `ui/features/AppIconSwitcher.kt` 与 Manifest 里三个 `activity-alias`，
   并把 `MainActivity` 改回自带 `LAUNCHER` intent-filter（**两者只能有一个**，
   否则桌面出现双图标或没有图标；`scripts/check-template.py` 就是查这个）。
10. **收尾**：删仓库根的 `素材库/`、`docs/`、`prompts/`、`scripts/`、`web-preview/`、`preview/`，
    改 `README.md`、`CREDITS.md`（保留第三方署名义务，见下）、`HANDOVER.md`；
    `LICENSE` 是 MIT，可保留。

每做完 1–2 步跑一次 `./gradlew :app:assembleDebug`，别攒到最后一起编。

## 4. 必须保留的署名

MIT 允许闭源商用，但**第三方来源的署名不能删**：`CREDITS.md` 里列的
backdrop-android / shapes（Apache-2.0）、Miuix（Apache-2.0，仅 O神主题参考视觉参数）、
Material Icons（Apache-2.0）、yz8023/UI2、KD一对A 与 ZTough 的视频规范来源等。
做法：把 `CREDITS.md` 精简成「你的 App 实际用到的那几项」，保留链接与许可证名，放进仓库或关于页。
删掉整份 CREDITS 再把 Apache-2.0 代码打进包里，是违反许可证的。

## 5. 已知坑（都是踩过的）

| 坑 | 现象 | 处理 |
|---|---|---|
| **中文文件名与中文标识符**（v2.10 已修） | v2.9.x 及更早：`android/` 里有 8 个中文文件名 + 18 种中文标识符（`fun 素材浏览器()`、`分类芯片`、`运动.Duration` 等）。Android Studio 重命名、部分 AI 工具、非 UTF-8 locale 的命令行会在这里出错（实测 `kotlinc` 直接抛 `InvalidPathException: Malformed input`） | 现已全部改英文：`Motion.kt`/`MotionModifiers.kt`/`InteractiveHighlight.kt`/`DragGestureDetector.kt`/`DampedDragAnimation.kt`/`MaterialBrowser.kt`/`MotionScreen.kt`/`WelcomeGuideScreen.kt`。旧中文名保留为 `@Deprecated` 别名（`ui/motion/LegacyMotionAliases.kt`、`ui/screens/LegacyScreenAliases.kt`），计划 v3.0 删除；**套壳时直接删这两个文件即可**。按 v2.9.x 抄走的代码做一次全局替换就能过编译——注意 `运动`→`Motion` 那个别名是转发 shim 而不是 typealias，因为 Kotlin 的 typealias 转发不了 `运动.Duration.Fast` 这类嵌套 object 访问（kotlinc 2.0.21 实测报 unresolved reference） |
| **`android/gradlew` 权限位漂移** | checkout/merge 后 `git status` 显示 `gradlew` 被改 | 提交前 `git checkout -- android/gradlew`；CI 里有 `chmod +x` 兜底 |
| **alpha 依赖** | `io.github.kyant0:backdrop-android:2.0.0-alpha03`、`shapes-android:1.2.0` 是 alpha 版，未来可能改 API 或下架 | 锁版本（已锁），别用动态版本号；升级前先跑玻璃页与底栏 |
| **CI 临时签名** | GitHub Actions 出的 release APK 用临时 keystore 签名，与你本地/上一版签名不一致 | 覆盖安装需先卸载；正式发布用你自己的 keystore（放仓库外，走 `~/.gradle/gradle.properties` 或 CI Secret） |
| **删 `素材库/` 后脚本报错** | `scripts/check-template.py` 报「缺失」 | 该脚本是模板维护者用的，套壳后连同 `scripts/` 一起删 |
| **玻璃在 API < 31 无效** | 低版本看不到折射/模糊 | 属设计降级，不是 bug；`ui/theme/` 里已按 API 分支，别为了低版本把整套玻璃换成半透明假玻璃后仍叫液态玻璃 |

## 7. 这套壳还缺什么（正在补）

对照同类模板（如 `chenaizhang/KernelSU-Style-UI-Kit`），本仓库当前**没有**：
应用内更新检查与下载、日志收集与分享、Markdown 渲染、大屏 NavigationRail 适配、
任何单元/设备测试、多语言基建、ViewModel + Repository 分层、路由表与深链。
补齐进度见 `docs/功能清单.md` 与仓库 Issue；其中「文案外置 + 中文标识符改英文」是套壳体验的最大根因，
优先级最高，但涉及 32 个文件，分批做。

> 与 `AGENTS.md` 红线的关系：红线「不改名」针对的是**把功能抄进宿主项目**的人
> （防止各自发明名字导致版本分叉）；**把本仓库当壳**时改包名、删演示页、把中文文件名改英文都是允许且推荐的。
> 两条路不要混着走。
