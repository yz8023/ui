## F01 应用图标切换【唯一权威，换图标只认这一个】

- **效果**：设置页点选，桌面图标在预置的多套图标间即时切换，杀掉重进不恢复错乱。
- **适用**：任何 Android 宿主（机制与 UI 框架无关）。**不适用**：想运行时生成任意图片当图标（做不到，图标必须预置在 APK 里）。
- **唯一权威源码**：
  - `android/app/src/main/java/com/monkeycode/liquidui/ui/features/AppIconSwitcher.kt`
  - `android/app/src/main/AndroidManifest.xml`（三 alias 段）
  - 资源：`res/mipmap-anydpi-v26/ic_launcher{,_galaxy,_coral}.xml`、`res/drawable/ic_launcher_foreground{,_galaxy,_coral}.xml`、`res/values/colors.xml`（三个背景色）
  - 接入点：`ui/screens/SettingsScreen.kt` 的「应用图标」区调用 `AppIconPicker(...)`
- **镜像**：`素材库/应用图标切换/`（已与权威对齐）。
- **机制（唯一路线）**：`MainActivity` 本体**不带** LAUNCHER intent-filter；每个图标 = 一个
  `<activity-alias>`（`enabled` 仅默认那个为 true），运行时 `setComponentEnabledSetting` **先启用目标、再逐个禁用其余**，标志 `DONT_KILL_APP`。当前是谁不另存偏好，直接读组件真实启用状态。
- **在宿主上落地要改的只有**：包名/组件名前缀（`.icon.Default` 等保持相对名写法，拼 `ComponentName` 时用 `packageName + ".icon.Default"` 完整类名）、图标资源换成你的图（保持 `ic_launcher_*` 命名与 adaptive-icon 三层结构：background/foreground/monochrome）、设置页入口换成你自己的 UI（View 宿主用普通列表/弹窗即可，见提示词附的 Java 版）。
- **红线**：
  1. 不许混用 F02 的「MainActivity 本体带 LAUNCHER」结构；
  2. 不许把图标载荷换成裸 PNG drawable（会在不同桌面被裁剪/留白，且与本模板验证过的方案不一致）；
  3. 不许先禁用旧的再启用新的（瞬间无入口，部分桌面会把图标直接抹掉）；
  4. alias 必须 `exported="true"`（API 31+ 强制）。
- **验收清单**：
  - [ ] 编译通过；Manifest 合并后有且仅有 1 个 `enabled=true` 的 LAUNCHER 组件（用 Android Studio 的 Merged Manifest 或 `aapt2 dump xmltree` 核对）
  - [ ] 真机逐套点选：每套桌面图标正确变化，无双图标、无消失（个别桌面需等数秒/回桌面，属正常，要写明等待现象）
  - [ ] 切换后点桌面图标能正常进 App；杀进程重进，选中态与桌面一致
  - [ ] 从任意一套切回默认，行为同上
- **失败指纹**：

| 现象 | 原因 | 改法 |
|---|---|---|
| 点了没反应 | `ComponentName` 用了相对类名（`.MainActivityXxx`）未拼包名；或 ROM 拦截后被 `runCatching` 吞了没提示 | 用完整类名；切换后逐个读回 `getComponentEnabledSetting` 校验，不一致要 Toast 明示（mt v5.71 的教训） |
| 桌面出现两个图标 | 混用了 F02 结构，或某个 alias 的 `enabled` 没互斥 | 回到本节 Manifest 结构逐行核对 |
| 切换后 App 被杀/图标消失 | 先禁后启造成瞬间无入口 | 改为先启目标、后禁其余 |
| 预览图崩溃/空白 | 拿 mipmap 自适应 XML 当 `painterResource` 预览 | 预览用 foreground drawable（示例现行做法） |

- **难度**：C ★☆☆ / V ★☆☆（Java 等价代码见 `prompts/01-换图标-含Java版.md`）

## F03 液态玻璃主题【根基功能，Compose 专有】

- **效果**：真 backdrop 玻璃（采样身后内容→模糊/折射/高光）、7 套配色、玻璃/普通/MD3 三态、透明度/折射等旋钮。
- **适用**：Kotlin+Compose 且能升到上表版本基准的宿主。**不适用**：View/Java 宿主（不可直接移植，见 `00-新人入口` 路线 C，先确认是迁 Compose 还是做改名的磨砂近似）；Kotlin<2.3 或 compileSdk<36 且不许升级的宿主。
- **唯一权威源码**：`ui/theme/{Color,Shape,Type,Theme}.kt`、`ui/components/Glass.kt`、
  根部接线 `ui/navigation/AppRoot.kt`、参数状态 `ui/screens/AppSettingsState.kt`（`AppChrome` 字段组）。
- **镜像**：`素材库/液态玻璃主题/代码/`（5 文件与权威一致）。
- **必须一起复制**：上面 5 个类文件 + AppRoot 的双层 backdrop 录制段
  （`auroraBackdrop` 录装饰层、`contentBackdrop` 录页面层、`LocalGlassBackdrop`/`LocalGlassContentBackdrop` 两个 CompositionLocal）。只抄 `Glass.kt` 不接根部录制 = 玻璃永远采不到东西，只剩半透明 tint（最常见假成功）。
- **接线要点**：`LiquidUITheme(themeMode, visualMode, palette, customSeed, customShade, chrome=AppChrome(...))` 包根；
  设置状态用 `updateXxx` 方法改（不要写 `setXxx`，会与属性 setter 撞 JVM 签名）；弹窗必须同窗（见 F10 的 `GlassDialogHost`）。
- **红线**：不许用「半透明背景+白色描边」自绘冒充真玻璃交付；不许跨 `Dialog` 窗口指望采样；
  API<33 无 lens 属正常降级，要写进汇报，不许宣称全量实现。
- **验收清单**：
  - [ ] 编译通过；版本与基准表逐项一致
  - [ ] 玻璃模式下卡片能看见身后光斑/壁纸被折射（滑动页面时折射内容跟着动），切普通/MD3 后变实心
  - [ ] 7 套配色+昼夜切换无闪烁错位；设置页透明度/折射滑块实时生效
  - [ ] 弹窗（同窗）是真玻璃；减少动效开启后内容直接可见
- **失败指纹**：

| 现象 | 原因 | 改法 |
|---|---|---|
| 面板全是实心/只有 tint | 没接根部 backdrop 录制，或 `visualMode` 不在 Glass，或 `LocalGlassBackdrop` 没 provide | 按 AppRoot 逐段对照，先让一张 `GlassCard` 在首页出真折射再铺全 App |
| 编译找不到 backdrop 类/Kotlin 元数据报错 | compileSdk<36、Kotlin 降版、或照旧文档装了 shapes 0.1.1 | 对齐基准表，`gradle.properties` 保留 `android.suppressUnsupportedCompileSdk=36` |
| 弹窗是实心块 | 用了系统 `Dialog`（独立窗口） | 改 `GlassDialogHost` 同窗浮层（F10） |
| View 宿主「抄完满屏报错」 | 路线选错 | 停。回 `00-新人入口` 路线 C 重新确认 |

- **难度**：C ★★☆ / V 不可直接移植（路线 C）

## F04 主题色配置与切换（示例内现行体系）

- **效果**：跟随系统/浅/深三态、7 套预设配色、自定义种子色、浅深平滑过渡。
- **唯一权威源码**：`ui/theme/Theme.kt`（`PaletteId`/`ThemeMode`/`schemeFor`/`seedSchemeFor`）+
  `AppSettingsState` 的 `themeMode/palette/customSeed/customShade` + `SettingsScreen.kt`「风格/外观」区。
- **特别警告（历史坑）**：`素材库/主题色配置与切换/` 里是另一套 YunX 的 `ThemeController` 体系，
  与示例现行 Palette 体系**不是同一套**，其镜像代码还有类名引用不一致与种子色 TODO 占位（文件头已加横幅）。
  **不要把两套主题体系同时接进一个 App**（会出现两个状态源、改一处不生效）。新接入二选一，默认选示例现行体系。
- **红线**：种子色生成不许用占位实现冒充完成；状态只许有一个来源（`AppSettingsState` 或你自己的单一状态类）。
- **验收**：三态与配色逐项切换即时生效且杀进程恢复；自定义取色后全 App 色板一致变化。
- **难度**：C ★★☆ / V ★★☆（思路移植：用宿主主题机制复刻 token，不要抄 Compose 代码）

- **效果**：当前外观/玻璃/动效偏好导出 JSON 到剪贴板，粘贴导入恢复。
- **唯一权威源码**：`AppSettingsState.exportThemeJson()/importThemeJson()` + `SettingsScreen.kt` 内的 `ThemeConfigTransferCard`（约 508 行起）。

## F06 网络壁纸与离线缓存

- **效果**：输入图片 URL→下载校验（限 20MB、超时、解码校验、降采样）→WebP 原子写入私有目录→界面只读本地缓存，源失效仍可用；本地图片同样复制进缓存。
- **唯一权威源码**：`ui/features/WallpaperStore.kt`、`ui/features/SystemWallpaper.kt`、`ui/screens/WallpaperSettings.kt`，背景消费在 `AppRoot.kt` 的壁纸层。
- **前置**：F03（壁纸作为 backdrop 被玻璃折射是 Compose 部分）；`INTERNET` 权限；设置状态的 `wallpaperMode/cachedWallpaperPath/networkWallpaperUrl/wallpaperRevision`。
- **系统壁纸（对照 pan-x/YunX 修复，两轮）**：第一轮去掉无效的 `READ_MEDIA_IMAGES` 权限门（该权限与 WallpaperManager 无关，拒绝即永久进不去），改为直接同步读 `WallpaperManager.drawable` 并 try/catch 降级、回前台重读——但在 Android 14+ 上仍然读不到。第二轮扒 pan-x 源码才发现它真正的解锁前提：**pan-x 清单声明了 `MANAGE_EXTERNAL_STORAGE`，且它的下载流程会跳系统设置页（`Settings.ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`）引导用户开启「所有文件访问」**；官方文档同样写明 Android 14+ 只有持有该权限的 app 能读到真实壁纸。现行实现已完整照做：Manifest 声明 `MANAGE_EXTERNAL_STORAGE`、设置页选「系统壁纸」时未授权则自动跳系统设置页（读不到时也有按钮可再跳）、授权返回后 bump revision + 根部回前台重读立即生效；读取走双路（`drawable` 优先，`getWallpaperFile(FLAG_SYSTEM)` 兜底）。
- **红线**：不许把远程 URL 直接给图片组件当「已缓存」用；写入必须临时文件+原子替换；大图必须降采样防 OOM；不许为读壁纸申请 `READ_MEDIA_IMAGES`；不许只抄 `getDrawable()` 那一行就宣称修好——清单声明 + 设置页引导 + 返回重读缺一不可；未授权时不许静默假装读取成功。
- **验收**：断网/改掉源 URL 后重启，壁纸仍在；超大图不崩；选本地图后撤掉原图仍显示；系统壁纸：Android 14+ 点「系统壁纸」能跳去开「所有文件访问」，开启返回后背景变成当前桌面壁纸，设置页状态变为「已读取」。
- **难度**：C ★★☆ / V ★★☆（缓存逻辑可移植，折射消费不可）

## F08 底部导航栏（液态玻璃底栏）

- **效果**：可拖拽、弹簧吸附、按压放大+高光跟随的玻璃底栏；非玻璃模式自动降级为 Material3 `NavigationBar`。
- **唯一权威源码**：`ui/components/LiquidBottomTabs.kt` + `AppRoot.kt` 里采样 combined backdrop 的接线段 + 页面列表 `bottom≈108.dp` 预留。
- **前置（缺一不可）**：F03（双层 backdrop）+ F09（`DampedDragAnimation`/`InteractiveHighlight`/`Motion`）。
  底栏采样的是 `rememberCombinedBackdrop(aurora, content)`，少录一层都会「玻璃但不对劲」。
- **红线**：选中位置必须是**槽位空间浮点值**（0..n-1）而不是像素坐标（mt 的 Java 复刻版曾因像素钳位导致首页永远点不到，见其 `LiquidBottomBarView` 注释）；View 宿主不许把本组件「翻译」成交付（要么迁 Compose，要么用宿主底栏并改名汇报）。
- **验收**：逐个标签点选+整条拖拽松手吸附都准，首/尾标签可达；内容能从底栏下方滚过被折射；切普通模式底栏变实心且功能不变。
- **难度**：C ★★☆ / V 不可直接移植

## F09 动效系统

- **效果**：全局阻尼旋钮、按压压扁、冲击抖动、呼吸、错峰入场、减少动效降级，全部 token 化（一处调参全 App 生效）。
- **唯一权威源码**：`ui/motion/` 六文件（`Motion.kt`/`MotionModifiers.kt`/`DampedDragAnimation.kt`/`InteractiveHighlight.kt`/`DragGestureDetector.kt` + `LegacyMotionAliases.kt`）。v2.10 起标识符与文件名全部英文；`LegacyMotionAliases.kt` 里保留 `@Deprecated` 的中文别名（`运动`/`交互高亮`/`阻尼拖拽动画`/`交错展示`/`Modifier.按压缩放`/`冲击抖动`/`闲置呼吸`），计划 v3.0 删除。
- **接线**：根部 `SideEffect { Motion.motionDamping.floatValue = settings.motionDamping }`；入场动画 `enabled` 必须接 `reducedMotion`。
- **红线**：调用点不许写临时 `spring(...)` 魔法数，一律取 `Motion` token；`remember` 的 key 必须含 `damping`，否则滑块拖了没反应。
- **验收**：设置页拖阻尼滑块，全 App 弹簧手感即时变；开减少动效，列表直接可见不空白；冲击只抖一次不糊。
- **难度**：C ★★☆ / V ★★☆（参数思想可借，Compose Modifier 不可直抄）

## F11 状态反馈组件

- **效果**：加载+骨架、空态、错误（带重试）、成功、离线、信息条、指标卡。
- **唯一权威源码**：`ui/components/Feedback.kt`。**注意**：`素材库/玻璃常用组件/代码/Feedback.kt` 与
  `素材库/状态反馈组件/代码/Feedback.kt` 是同一份内容的两处镜像，**只能抄一份**，两份一起进工程会重复声明。
- **红线**：错误态必须带可操作入口（重试/设置/重新导入），只写一句「加载失败」算未完成。

- **红线**：① token 不许硬编码进客户端；② APK 只落私有缓存目录，不写公共下载目录；③ 禁止 `Uri.fromFile`（Android 7+ 抛 `FileUriExposedException`）；④ 版本比较必须按语义化拆段比（`2.10.0 > 2.9.0`），不许字符串直接比；⑤ 失败态与最新态不许共用文案，未授权安装不许静默失败。
- **验收**：有网检查返回三态之一并显示耗时；断网时文案是「无法解析 api.github.com」这类可读原因；HTTP 403 提示 API 限流；下载显示百分比与 MB、可取消；下完调起安装器；未授权时出现两个兜底按钮；设置页更新日志是 Markdown 渲染而非纯文本。
- **文档原件**：`素材库/工具与基建/`（实现方案 / 环境要求 / 参考来源 + `代码/` 七份镜像）。
- **难度**：C ★★★ / V ★★★★（View 宿主需自己起线程、下文件、配 FileProvider，Compose 侧只有状态展示）

## F19 运行日志与分享（U02）

- **效果**：应用自己的环形缓冲日志（400 条上限），四级别 D/I/W/E，可按级别与关键词过滤；设置页「运行日志」底部面板可查看全文、复制、系统分享、清空；缓冲里是**真实运行记录**（更新检查全流程、通知发送、`POST_NOTIFICATIONS` 授权结果），不是面板自造数据。
- **唯一权威源码**：`ui/features/toolkit/AppLog.kt`（`AppLogLevel` / `AppLogEntry` / `AppLog.d/i/w/e` / `clear` / `counts` / `dump` / `buildShareIntent` / `persist` 钩子）、接入点 `ui/screens/SettingsScreen.kt` 的 `AppLogPanel` 与 `sendNotificationPreview` 内的日志调用、演示 `ToolkitDemo.kt`。
- **必须一起复制**：`AppLog.kt` 单文件即可（无其他依赖）。
- **接线**：在真实调用点打日志——网络请求起止与耗时、权限授予/拒绝、异常捕获（`AppLog.e(tag, msg, throwable)` 会带异常类名与 message）、关键用户动作。分享用 `Intent.createChooser(AppLog.buildShareIntent(...))` 并外包 `runCatching`。需要跨重启留存时给 `AppLog.persist` 赋一个写 `getExternalFilesDir(null)` 的实现，自己处理轮转与体积上限。
- **依赖与权限**：零新增依赖、**零权限**（只存内存不落盘）。
- **红线**：① 日志里不许出现 token、密码、带 query 的完整 URL、手机号；② 不许只打 logcat 就指望用户能给日志（Android 4.1 起读不到）；③ 缓冲必须有上限；④ 分享失败必须有复制兜底；⑤ 不要用「整块 String 替换 state」的方式存日志（大日志时每帧重建全文会卡）。

- **难度**：C ★★☆ / V ★★☆

## F20 Markdown 渲染（U03）

- **效果**：`MarkdownText(source)` 直接渲染 Markdown，颜色全走 `MaterialTheme.colorScheme`（深色模式自动适配）。支持 `#`~`######` 标题、`**粗**`、`*斜*`/`_斜_`、`` `行内码` ``、`[文字](链接)`（可点，走 `LocalUriHandler`）、``` / ~~~ 围栏代码块（带语言标签、可横向滚动、`SelectionContainer` 长按复制）、`- * +` 无序列表、`1.`/`1)` 有序列表（保留起始编号）、`>` 引用（左侧 3dp 主色竖条）、`---`/`***`/`___` 分隔线。演示页可切三篇样例，也能在输入框里改文字实时重渲染，并显示真实解析统计（块数、各类块数量、行内节点数、链接数）。
- **唯一权威源码**：`ui/features/toolkit/MarkdownText.kt`（`MdBlock` / `MdInline` / `MarkdownParser.parse` / `parseInlines` / `rememberInlineText` / `MarkdownText`）。
- **必须一起复制**：单文件即可。F18 的更新日志渲染依赖它。
- **接线**：任何页面塞 `MarkdownText(source)` 即可；解析结果 `remember(source)` 缓存，长文档列表里也不会每帧重解析。
- **依赖与权限**：**零第三方依赖**（自写解析器），需要 Compose UI **1.7.0+**（`LinkAnnotation` / `withLink`）；BOM 更低时链接需降级写法。无权限。
- **不支持**：表格、图片、嵌套列表、任务列表、HTML 内联、脚注。需要时扩解析器，或改引 `org.commonmark:commonmark`（约 200KB），接口边界已收窄在 `MarkdownParser.parse`。
- **红线**：① 不用 WebView 渲染（主题不跟随、深色模式另写 CSS、初始化开销大）；② 围栏代码块内部不许再做块级/行内解析；③ 不用已废弃的 `ClickableText` + 手算 offset；④ 代码块不许折行（要横向滚动）；⑤ 行内解析找不到闭合符时必须按普通字符处理（未闭合的 `*` 不能吞掉后文）。
- **验收**：三篇样例逐项渲染正确；未闭合 `*` 不吞后文；`snake_case` 不被拆成斜体；代码里的 `#` 不变标题；链接点击能打开浏览器；解析统计随内容变化；输入框实时重渲染不卡。
- **难度**：C ★★☆ / V ★★★（View 宿主可用 `SpannableStringBuilder` 走同一套解析结果）

## F21 自适应导航 NavigationRail（U04）

- **效果**：同一套路由数据，窗口宽度 <600dp 用底部 `NavigationBar`、≥600dp 用侧边 `NavigationRail`、≥840dp 侧栏再显示文字标签。演示页用 `BoxWithConstraints` + 宽度滑杆（360–1000dp）把外壳塞进受限容器，**手机上就能实时看到两种布局切换**，同时显示当前真机窗口分级与演示容器分级。
- **唯一权威源码**：`ui/features/toolkit/AdaptiveNav.kt`（`AppWindowClass` / `windowClassOf` / `rememberAppWindowClass` / `AdaptiveNavItem` / `AdaptiveAppShell` / `AdaptiveBottomBar` / `AdaptiveSideRail`）。
- **必须一起复制**：单文件即可。
- **接线**：`AdaptiveAppShell(items, selectedIndex, onSelect) { 页面内容() }` 包住现有导航；`selectedIndex` 用 `rememberSaveable` 存（旋转/形变不丢）；想用官方分级就把 `rememberAppWindowClass()` 换成 `calculateWindowSizeClass()`（需加 `material3-window-size-class` 依赖），其余代码不动。本仓库 `AppRoot.kt` **未改**（三套底栏变体，沙箱无法验证视觉回归），要接就替换 `SolidBottomTabs` 那一支。
