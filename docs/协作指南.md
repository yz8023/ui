# 多人协作与冲突规避指南

本仓库适合多人并行补功能。为了避免两个人同时改 `main` 造成覆盖，建议统一使用以下流程。

## 1. 分支规则

- 禁止直接向 `main` 推送功能代码；
- 每个任务单独分支：

```bash
git switch -c agent/<功能名>-YYYYMMDD
```

示例：

```bash
git switch -c agent/feature-completion-20260922
```

## 2. 开工前同步

```bash
git fetch origin
git rebase origin/main
```

如果本地没有提交，也可以直接：

```bash
git pull --rebase origin main
```

## 3. 文件范围尽量拆开

推荐按功能拆分：

| 任务 | 主要修改范围 |
|---|---|
| 新增素材目录 | `素材库/<功能名>/` |
| 示例 App 接入 | `android/app/src/main/java/...` |
| 文档更新 | `README.md` / `docs/` |
| 构建流程 | `.github/workflows/` / `android/*.gradle.kts` |

两个人同时工作时，尽量不要同时重写同一个大文件，例如 `SettingsScreen.kt`、`README.md`。

## 4. 提交前检查

```bash
git status
git diff --check
grep -RIn --exclude-dir=.git 'gh[pousr]_' . || true
```

`git diff --check` 用于发现空白错误；token 前缀检查用于避免把 GitHub Token 写入仓库。

## 5. 推送策略

推送自己的功能分支：

```bash
git push -u origin agent/<功能名>-YYYYMMDD
```

开 Pull Request 后让另一位协作者审阅并合并。

如需在自己的分支上 rebase 后强推，只允许使用：

```bash
git push --force-with-lease
```

不要使用 `--force`。

## 6. 冲突处理

如果 rebase/merge 出现冲突：

1. 先看冲突文件：`git status`；
2. 打开文件，保留双方必要修改；
3. 运行 `git diff --check`；
4. 能构建时运行 `./gradlew :app:assembleDebug`；
5. 再继续 `git rebase --continue` 或提交 merge。

## 7. Token 安全

不要把 GitHub Token 写入：

- 代码文件；
- README / 文档；
- `.git/config`；
- shell 脚本；
- CI 日志。

如果 Token 曾经出现在聊天、日志或截图里，应立即在 GitHub 后台 revoke 并重新生成。
