# 新人入口 · 先读这个（5 分钟选对路线，避免返工）

> 本仓库以前最大的问题：拿到模板的人（或 AI）不知道**先判断什么**，直接抄，
> 抄不动就自己发明，于是每个人的成果都和模板不一样。这页就是开工前的体检表。

## 第 0 步：本仓库到底是什么

- `android/` = **唯一能编译、能运行的权威示例**。想看任何功能的真实效果、真实代码，以这里为准。
- `素材库/<功能>/代码/` = 从示例工程拆出来的**镜像副本**，方便你按功能取文件。与示例不一致时听示例的。
- `docs/功能逐项手册.md` = 每个功能（F01–F13）的完整说明书：抄哪些文件、改哪里、怎么验收、错了长什么样。
- `prompts/` = 给 AI 助手用的现成提示词；把模板交给别人/AI 时，**把提示词和仓库一起给**，不要只给仓库地址。
- `AGENTS.md` = 给 AI 的硬规则。对方用 AI 开发时，要求它先读这个文件。

## 第 1 步：给你的项目做体检（1 分钟，必做）

打开你的工程，回答 4 个问题：

| # | 问题 | 怎么看 |
|---|---|---|
| 1 | UI 用什么写的？ | 布局是 XML + Activity/Fragment（View 体系），还是 `@Composable` 函数（Compose）？ |
| 2 | 语言？ | `.java` 还是 `.kt`？`build.gradle` 里有没有 Kotlin、Compose 插件？ |
| 3 | 版本？ | `compileSdk` 多少？`minSdk` 多少？ |
| 4 | 你要整套还是单个功能？ | 想要整套玻璃风格 App，还是只给现有 App 加一个功能（如换图标）？ |

## 第 2 步：按体检结果选路线（只能选一条，不许混）

### 路线 A：整壳复制（推荐给新项目 / 愿意换 Compose 的项目）

把 `android/` 整个复制成新工程，改包名和应用名，删掉不要的页面。
这是**唯一能保证效果和模板完全一致**的路线。具体步骤见 `docs/组合指南.md` 第 2 节。

### 路线 B：Compose 项目加单个功能

你的项目已经是 Kotlin + Compose 时用这条。去 `docs/功能逐项手册.md` 找到功能编号，
按它的「文件清单」整文件复制 → 只改 `package` 和 `R` → 按「接线」接入 → 按「验收清单」打勾。

### 路线 C：View / Java 项目（最容易踩坑，先想清楚再动手）

你的项目是 XML + Java/Kotlin-View（如老论坛、工具类 App）时：

| 想要的功能 | 能否直接抄 | 正确做法 |
|---|---|---|
| 换图标（F01） | ✅ 机制与 UI 框架无关 | 用手册 F01 的 Java 等价写法（提示词 `prompts/01-换图标-含Java版.md` 附完整 Java 代码），**不要**去抄 Compose 的选择器 UI |
| 主题色/深色模式（F04） | ⚠️ 思路可借，代码不可抄 | Compose 的 `ColorScheme` 在 View 里不存在；用你项目的主题机制重做配色 token，功能名保持但实现按 View 写，并在汇报里注明 |
| 液态玻璃（F03） | ❌ **不能直接移植** | 真玻璃靠 Compose 的 backdrop 采样 + RuntimeShader，View 体系没有对应 API。只有两条路：①把要用玻璃的那个页面迁到 Compose（成本高，需引入 Kotlin+Compose 全套）；②在 View 里做「磨砂近似」（截图模糊/半透明+高光描边），**必须改名为「磨砂玻璃（近似）」交付**，不许叫真液态玻璃。选哪条要先和需求方确认，见 `prompts/03-液态玻璃-View项目先看这个.md` |
| 底栏/动效/玻璃组件（F08/F09/F10） | ❌ 同上 | 它们都建立在 Compose 玻璃之上；View 里请用你原有控件体系实现同等交互，不要把 Compose 文件「翻译」成自定义 View 后声称对齐模板（历史事故重灾区，参数再像也不是同一个东西） |
| 壁纸缓存（F06） | ⚠️ 下载/缓存逻辑可借 | `WallpaperStore` 的下载校验、原子写入逻辑可移植；「把壁纸录进 backdrop 给玻璃折射」这步是 Compose 专有，View 里只做到设为页面背景为止 |
| 引导页/权限/协议/状态反馈（F07/F11/F12/F13） | ⚠️ 抄结构不抄代码 | 页面结构、文案组织、状态清单可以照着做；UI 代码用你项目的体系写 |

> 一句话记忆：**图标是框架无关的，可以放心学；玻璃是 Compose 专有的，View 项目硬学必然学出四不像。**

### 路线 D：环境不满足就停

JDK<17、`compileSdk` 升不到 36、又不许改构建配置时，F03/F08/F10 做不了。
停下来报告缺什么（对照手册的「环境门槛」），不要用低版本替代库凑一个「类似玻璃」交差。

## 第 3 步：开工前写一页「开工表」（交给人或 AI 都一样）

```
目标功能：F__ ＿＿＿＿
我的项目：语言＿＿ / UI 体系＿＿ / compileSdk＿＿ / minSdk＿＿
选定路线：A / B / C / D，理由：＿＿
将复制的文件（逐个）：＿＿（来源以 android/ 权威路径为准）
将修改的现有文件（逐个）：＿＿
明确不做：不改名 / 不换机制 / 不混另一套变体 / 不升级依赖版本
验收方式：编译命令＿＿ + 手册验收清单第＿项 + 真机行为＿＿
```

开工表没写完就动手，是以前所有返工的共同起点。

## 第 4 步：做完按手册验收，不要凭感觉

每个功能在手册里都有三件套：**验收清单**（逐项打勾）、**失败指纹表**（现象→原因→改法）、
**汇报模板**。涉及桌面图标、真机玻璃效果的，必须写明真机现象或 adb 输出，不许只写「已完成」。

## 常见误选速查（前人踩过的）

| 误选 | 后果 | 正解 |
|---|---|---|
| 同时参考「应用图标切换」和「桌面图标动态切换」两套 Manifest | 双图标 / 无图标 / 切了没反应，反复返工 | 只用 F01 一套（见手册 F02 的合并说明） |
| 把素材库代码拷来后整体改中文名/英文名 | 跨文件引用断裂，越改越乱 | 只改 `package` 和 `R`，名字保持原样 |
| View 项目把 Compose 玻璃「翻译」成自定义 View | 参数抄得再像也不是 backdrop 采样，效果对不上还说不清 | 路线 C 二选一，先确认再动手 |
| 弹窗用了系统 `Dialog` 还想真玻璃 | 跨窗口采不到 backdrop，玻璃变实心 | 用同窗浮层 `GlassDialogHost`（F10） |
| 版本凭文档旧数字装依赖 | 编译失败/元数据不兼容 | 一切版本以 `android/gradle/libs.versions.toml` 为准 |
