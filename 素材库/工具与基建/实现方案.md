# 工具与基建 · 实现方案

> 对应手册 **F18–F21**，条目编号 **U01–U04**（U 编号独立于手册 F 编号、UI2 的
> F/G/M/V/X/W/T、数据查询 Q、弹窗术语 P；引用时写「U01」或「手册 F18」）。
> 出处见 `参考来源.md`，运行环境见 `环境要求.md`。

## 1. 这四条解决什么

前 17 个功能点大多是「界面怎么做」，这四条是「一个 App 要真能用还缺什么」：

| 编号 | 手册 | 名称 | 没有它会怎样 |
|---|---|---|---|
| U01 | F18 | 应用内更新检查 | 侧载分发的用户永远停在旧版，你只能发帖喊人手动下 |
| U02 | F19 | 运行日志与分享 | 用户说「点了没反应」，你拿不到任何现场信息（logcat 读不到） |
| U03 | F20 | Markdown 渲染 | 更新日志/说明页只能塞 WebView，主题不跟随、深色模式另写一套 |
| U04 | F21 | 自适应导航 | 折叠屏展开、平板、桌面窗口下底部栏占掉一大块纵向空间 |

四条的共同点：**都是真实可运行的代码，不是示意图**。示例 App 自己也用上了 U01/U02——
设置页的「更新与日志」分区打的就是本模板仓库的 GitHub Releases，日志面板里能看到
更新检查、通知发送、权限结果的真实记录。

## 3. 每条的真实实现要点

### U01 应用内更新检查（F18）

```
HttpURLConnection GET api.github.com/repos/{owner}/{repo}/releases/latest
  → org.json 解析 tag_name / published_at / body / assets[]
  → 挑 APK 附件（优先 .apk 后缀，其次名字含 release）
  → isNewer(current, latest)：去 v 前缀、按 . 拆段、逐位比、缺位补 0
  → 三态 UpdateState：UP_TO_DATE / UPDATE_AVAILABLE / FAILED
下载：cacheDir/updates/xxx.apk.part → renameTo → 比对 Content-Length 防半包
安装：FileProvider.getUriForFile + ACTION_VIEW + application/vnd.android.package-archive
     + FLAG_GRANT_READ_URI_PERMISSION；Android 8+ 先查 canRequestPackageInstalls()
兜底：未授权 → ACTION_MANAGE_UNKNOWN_APP_SOURCES；调不起安装器 → 浏览器下载
```

- 当前版本从 `PackageManager.getPackageInfo().versionName` 读，**不依赖 BuildConfig**（宿主不用开 `buildConfig = true`）。
- 失败按异常类型给不同文案：`UnknownHostException`（无网/DNS）、`SocketTimeoutException`（超时）、`SSLException`（TLS）、HTTP 403（API 限流）、404（没有 Release）。
- 每次请求、下载、安装都写 `AppLog`，与 U02 打通。
- 演示页另有「三态预览」，**明示为模拟数据**，用于无网时看清界面分支；模拟态下下载按钮禁用。

### U02 运行日志与分享（F19）

- `object AppLog` 持 `mutableStateListOf<AppLogEntry>`（Compose 可直接观察，写入即刷新）。
- 上限 400 条，超出丢最旧；写入 `@Synchronized`；同时打一份到 `android.util.Log`。
- 每条带单调递增 `seq`；导出首行写「共 n 条（缓冲 m/400）· 时间范围」，对方能判断日志是否被截断。
- `dump(level, keyword)` 过滤导出；`buildShareIntent()` 返回 `ACTION_SEND` + `text/plain`，
  调用方用 `Intent.createChooser` 包一层并 `runCatching`（用户可能没装能接收的应用），失败提示改用复制。
- 异常入日志带 `类名: message`；`persist` 钩子留给需要落盘的宿主（默认不落盘 = 不需要存储权限）。
- **真实调用点已接**：更新检查全流程、通知发送、`POST_NOTIFICATIONS` 授权结果。

### U03 Markdown 渲染（F20）

- 两层解析：块级按行扫描 → `MdBlock`（Heading/Paragraph/BulletList/OrderedList/CodeBlock/Quote/Rule）；
  行内按字符扫描 → `MdInline`（Text/Bold/Italic/Code/Link）。
- 围栏代码块（``` / ~~~）内部**原样保留**，不再解析（否则代码里的 `#`、`-` 会被当标题和列表）。
- 列表/引用聚合连续行后 `i--` 回退一格，避免吃掉下一行。
- 行内优先级：行内码 → 链接 → 粗体 → 斜体；找不到闭合符就按普通字符追加（未闭合的 `*` 不会吞掉后文）；
  `_` 只在后面不是字母数字时闭合（不拆 `snake_case`）。
- 渲染：`buildAnnotatedString` + `withStyle(SpanStyle(...))`；链接用 `withLink(LinkAnnotation.Url(url))`，
  点击交给 `LocalUriHandler`（不用已废弃的 `ClickableText`，也不用自己写 Intent）。
- 代码块 `SelectionContainer` 可长按复制 + `horizontalScroll` 不折行；解析结果 `remember(source)` 缓存。
- 演示页可切三篇样例（更新日志/语法清单/隐私说明），也能**直接在输入框里改文字实时看渲染**，
  并显示真实解析统计（块数、各类块数量、行内节点数、链接数）。
- 不支持：表格、图片、嵌套列表、任务列表、HTML 内联（要就扩解析器，或引 `org.commonmark:commonmark`）。

### U04 自适应导航（F21）

- `AppWindowClass`：COMPACT(<600dp) / MEDIUM(600–839) / EXPANDED(≥840)，断点沿用 Material 3。
- 宽度取 `LocalConfiguration.current.screenWidthDp`（**窗口**宽度，分屏/折叠屏/桌面窗口都对），
  旋转与形变自动重组，不需要监听器；`windowClassOf(Int)` 是纯函数，方便写单元测试。
- `AdaptiveAppShell`：COMPACT → `Column(内容 weight(1f) + AdaptiveBottomBar)`；
  其余 → `Row(AdaptiveSideRail + 内容 weight(1f))`。内容区永远拿整块剩余空间，宿主不用为两种布局各写内边距。
- 侧栏文字标签只在 EXPANDED 显示；`label` 参数**始终传 lambda**、内部按开关决定渲不渲染
  （条件式返回 `@Composable` lambda 会让类型推断变脆弱）。
- 底部栏 `alwaysShowLabel = items.size <= 4`。
- 演示页用 `BoxWithConstraints` + 宽度滑杆（360–1000dp）把外壳塞进受限容器，
  **手机上也能实时看到底部栏 ↔ 侧边栏切换**，并显示当前真机分级与演示容器分级。
- 刻意不引 `material3-window-size-class`：想用官方版把 `rememberAppWindowClass()` 换成
  `calculateWindowSizeClass()`，其余代码不动。

## 4. 接线（接到你的项目）

1. 复制 `features/toolkit/` 六个文件（4 个实现 + Spec + Demo）到宿主同包路径，只改 `package`。
2. U01 额外三件事：Manifest 加 `REQUEST_INSTALL_PACKAGES`；声明 FileProvider
   （`authorities="${applicationId}.fileprovider"`、`exported=false`、`grantUriPermissions=true`）；
   新建 `res/xml/file_paths.xml` 加 `<cache-path name="updates" path="updates/" />`。
   把 `AppUpdateChecker.DEFAULT_REPO` 改成自己的 `owner/repo`。
3. U02 在真实调用点补日志：网络请求起止与耗时、权限授予/拒绝、异常捕获、关键用户动作。
   只在日志面板里自己打自己没有意义。
4. U03 直接把 `MarkdownText(source)` 塞进任何页面；更新日志渲染就是 U01 + U03 的组合（示例 App 已这么用）。
5. U04 用 `AdaptiveAppShell(items, selectedIndex, onSelect) { 页面内容() }` 包住现有导航；
   `selectedIndex` 用 `rememberSaveable` 存，旋转不丢。本仓库的 `AppRoot.kt` **没有**改成自适应外壳
   （它有三套底栏变体：玻璃/O神/纯 Material，改动面大且无法在沙箱里验证视觉），
   要接的话按 `docs/组合指南.md` 的思路替换 `SolidBottomTabs` 那一支即可。
6. 目录/详情页依赖仓库内 `GlassCard`、`SectionTitle`、`AppIcons`；宿主没有就换成 `Surface`/`Text`/自己的图标。

## 6. 红线

1. 四条都必须真实可运行：U01 真发请求真下载、U02 真写真分享、U03 真解析真渲染、U04 真切布局。
   **不许用截图、静态卡片或假数据冒充**（演示里的「三态预览」已明示为模拟数据，且模拟态禁用下载）。
2. U01 不许把 GitHub token 硬编码进客户端；APK 只落应用私有缓存目录；未授权安装时必须给引导与兜底，不许静默失败。
3. U02 日志里不许出现 token、密码、带 query 的完整 URL、手机号——分享出去就是泄露。
4. U03 颜色全部走 `MaterialTheme.colorScheme`；不用 WebView；不用已废弃的 `ClickableText`。
5. U04 判断依据是窗口宽度而不是屏幕物理宽度；不许在 `onCreate` 里判一次就固定。
6. 宿主替换实现（例如改用 okhttp、改用 commonmark）后，仍按本模块名字交付就必须写明差异（与 `AGENTS.md` 红线 2 一致）。
