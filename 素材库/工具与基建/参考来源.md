# 工具与基建 · 参考来源

## 1. 这批功能是怎么定出来的

**本批（F18–F21 / U01–U04）不来自视频**，来自一次对照分析：把本仓库与
`chenaizhang/KernelSU-Style-UI-Kit`（下称 Kit）逐项对比，找出「他有我无」的缺口，
再挑出对宿主最有价值的四条落地。分析正文在仓库外的工作文档
`套壳难度诊断与补齐清单.md`（未随仓库发布），结论摘要如下。

| Kit 里对应的文件 | 本仓库的对应实现 | 差异 |
|---|---|---|
| `ui/util/Downloader.kt`、`LatestVersionInfo.kt`、`HomeUpdateCard` | `features/toolkit/AppUpdateChecker.kt` + 设置页 `UpdateCheckPanel` | Kit 用 `okhttp`；本实现用 `HttpURLConnection` + `org.json`，零新增依赖 |
| `material/SendLogBottomSheet.kt`、`miuix/SendLogDialog.kt`、`util/LogEvent.kt` | `features/toolkit/AppLog.kt` + 设置页 `AppLogPanel` | Kit 分双风格两套 UI；本实现一套逻辑 + 一个底部面板，宿主自己套风格 |
| `ui/component/markdown/GithubMarkdown.kt`、`MarkdownContent.kt` | `features/toolkit/MarkdownText.kt` | Kit 用 `org.commonmark:commonmark` 解析；本实现自写解析器，零依赖，代价是不支持表格/图片/嵌套列表 |
| `bottombar/NavigationRailMaterial.kt`、`NavigationRailMiuix.kt` | `features/toolkit/AdaptiveNav.kt` | Kit 按风格分两份；本实现按窗口宽度自动切 `NavigationBar`/`NavigationRail`，一份代码 |
| `util/DeviceNameHelper.kt`、`OemHelper.kt`、`component/ScrollToTop.kt` 等 | **本批未做** | 属于「批 A：测试基建 + 工具小包」，留待后续 |

Kit 仓库为 GPL-3.0。**本批没有复制它的任何代码**：只读了它的文件清单与公开文档
（`README.zh-CN.md`、`docs/GETTING_STARTED.zh-CN.md`）来判断「缺什么功能」，
实现、接口设计、文案全部独立撰写，因此本仓库继续以 MIT 发布不受影响。

## 2. 各条依据的公开规范/文档

| 条目 | 依据 | 用途 |
|---|---|---|
| U01 | GitHub REST API · Releases · `GET /repos/{owner}/{repo}/releases/latest`（docs.github.com） | 响应字段 `tag_name` / `name` / `body` / `published_at` / `assets[].{name,browser_download_url,size}`；未认证时限流 60 次/小时/IP |
| U01 | Android 开发者文档 · `FileProvider`、`REQUEST_INSTALL_PACKAGES`、`PackageManager.canRequestPackageInstalls()`、`Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES` | APK 分发与安装授权流程；Android 7+ 禁止 `file://` 跨应用暴露（`FileUriExposedException`） |
| U02 | Android 开发者文档 · `Intent.ACTION_SEND` / `EXTRA_TEXT`；自 Android 4.1 起普通应用无法读取完整 logcat | 「必须应用自己存一份日志」这个前提；分享走系统选择器 |
| U03 | CommonMark 规范（spec.commonmark.org）中对 ATX 标题、围栏代码、强调、链接、列表、引用、分隔线的定义 | 本实现只取其中的常用子集，语法判定口径与其一致（未逐条实现全部规则） |
| U03 | Compose UI 1.7 的 `LinkAnnotation` / `withLink`（developer.android.com 参考） | 链接点击交给 `LocalUriHandler`，替代已废弃的 `ClickableText` |
| U04 | Material 3 · Window size classes（compact <600dp / medium 600–839dp / expanded ≥840dp）与 Navigation rail 使用建议 | 断点数值与「宽屏用侧栏」的结论 |
| U04 | Android 开发者文档 · `Configuration.screenWidthDp` 在多窗口/分屏下反映窗口尺寸 | 用窗口宽度而非屏幕物理宽度分级 |

## 3. 哪些参数是本仓库自定的（不是规范里的）

以下数值没有权威出处，是按工程习惯定的，宿主可自行调整，改动点都在代码常量里：

| 参数 | 取值 | 位置 |
|---|---|---|
| 连接/读取超时 | 8s / 12s | `AppUpdateChecker.CONNECT_TIMEOUT` / `READ_TIMEOUT` |
| 下载读取超时、缓冲 | 60s / 64KB | `AppUpdateChecker.download` |
| APK 附件匹配规则 | 优先 `.apk` 后缀，其次名字含 `release` | `AppUpdateChecker.pickApkAsset` |
| 日志缓冲上限 | 400 条 | `AppLog.MAX_ENTRIES` |
| 日志时间格式 | `MM-dd HH:mm:ss.SSS`（`Locale.US`） | `AppLog.dump` |
| 行内码 / 代码块字号 | 13sp / 12sp（行高 18sp） | `MarkdownText` |
| 引用竖条宽度 | 3dp | `MarkdownText` |
| 侧栏内边距 / 条目间距 | 上下 8dp / 4dp | `AdaptiveSideRail` |
| 底部栏标签策略 | `alwaysShowLabel = items.size <= 4` | `AdaptiveBottomBar` |
| 演示宽度滑杆范围 | 360–1000dp | `ToolkitDemo.AdaptiveNavDemo` |

Material 的 600/840dp 断点**不是**自定值，来自 Material 3 窗口尺寸分级。

## 4. 演示里用到的数据说明

- U01 演示页的「三态预览」芯片会造出三条**模拟**结果（含一个假下载地址
  `https://example.invalid/…`），界面上明确标注「模拟态」，且模拟态下下载按钮禁用——
  这样无网时也能看清三种分支，又不会让人误以为真下载了。
  符合仓库 `docs/AI开发流程与需求描述规范.md` 里「模拟数据必须明示」那条。
- U01 的「真实检查更新」打的是 `yz8023/ui` 的真实 Release，返回内容随仓库发版变化。
- U03 的三篇样例（更新日志/语法清单/隐私说明）是为本模块写的演示文本，
  其中「v2.8.0 更新日志」内容与实际发版一致，但不是从 Release 页面抓的。
- U02 演示写入的日志是演示动作本身（点按钮就真写），另外 U01 的检查/下载与
  设置页的通知发送、权限结果也会写进同一个缓冲——那些是真实运行记录。
- U04 演示里的四个导航项（首页/素材/动效/设置）沿用 `Screen` 枚举的名称与图标，
  但演示容器是独立的，不与主壳导航联动。

## 5. 未采纳的替代方案（记录取舍）

| 方案 | 为什么没采纳 |
|---|---|
| `okhttp` 做更新检查 | 多一个依赖，而这里只需要一个 GET + JSON 解析；`HttpURLConnection` 够用且零成本 |
| `commonmark` 解析 Markdown | 多约 200KB 依赖；模板场景只需要常用子集，自写解析器 200 行可控。**宿主需要表格/图片时应该换成它**，接口边界已收窄在 `MarkdownParser.parse` |
| `material3-window-size-class` | 多一个依赖，而分级就是「量宽度 + 两个断点」；`windowClassOf` 是纯函数，宿主想换官方版改一行 |
| `WebView` 渲染 Markdown | 主题不跟随、深色模式要另写 CSS、初始化开销大、还要处理安全设置 |
| 日志落盘（`getExternalFilesDir`） | 默认不落盘可以完全免存储权限、进程被杀即清空不留痕；需要跨重启留存时通过 `AppLog.persist` 钩子扩展 |
| WorkManager 定时检查更新 | 模板不引入 `androidx.work`；检查由用户手动触发或宿主自己在启动时调一次即可 |
| 把 U04 直接接进 `AppRoot.kt` | 主壳有三套底栏变体（玻璃/O神/纯 Material），沙箱无法验证视觉回归，改了容易出「编译通过但看起来不对」的问题；因此只交付可复用外壳 + 可操作演示，接入步骤写在 `实现方案.md` §4 |

## 6. 与本仓库已有条目的边界

| 已有 | 关系 |
|---|---|
| 手册 **F10 通用组件** | `GlassCard`/`SectionTitle`/`PrimaryButton` 等是 F10 的产物；本模块的目录/详情页复用它们，但演示内部一律用自带原子控件（`TKChip`/`TKButton`/`TKKeyValue`/`TKNote`），保证整包可复制 |
| 手册 **F11 状态反馈组件** | F11 管加载/空态/错误/成功的组件；U01 的三态界面用的是同一套语义（显式状态枚举 + 可读失败原因），不重复实现组件 |
| 手册 **F16 后台数据查询规范（Q01–Q05）** | Q01 的「结果区回显条件+命中数+耗时」与 U01 的「三态+耗时」是同一思路；Q04 的 CSV 导出与 U02 的日志导出都用「系统分享 + 复制兜底」 |
| 手册 **F17 弹窗与提示术语（P01–P12）** | U02 的底部日志面板就是 P10 BottomSheet 的真实用法；U01 的失败提示遵循 P01/P07 的选型（阻塞结论用 Alert 语义、可恢复动作用 Snackbar 语义） |
| UI2 **V03/V05/V06/V07 等视频专题** | 那些条目来自视频取证；本批来自仓库对照分析，取证口径不同，见本文件 §1 |
