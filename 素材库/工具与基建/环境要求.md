# 工具与基建 · 环境要求

> 基准以 `android/gradle/libs.versions.toml` 为唯一可信来源；本文件只列本模块**额外**要注意的点。

| 项 | 值 |
|---|---|
| JDK | 17 |

| minSdk | **26** |

各条对版本的具体要求：

| 条目 | 最低要求 | 说明 |
|---|---|---|
| U01 更新检查 | minSdk 26 | `canRequestPackageInstalls()` 与 `ACTION_MANAGE_UNKNOWN_APP_SOURCES` 都是 API 26+；代码里已用 `SDK_INT >= O` 包裹，低于 26 直接走安装器 |
| U02 日志分享 | 无 | 纯内存 + `ACTION_SEND`，API 21 也能跑 |

| U04 自适应导航 | Material3 1.1+ | `NavigationRail`/`NavigationRailItem` 早已稳定；`alwaysShowLabel` 需要 M3 1.1+ |

## 2. 新增依赖

**无。** 四条全部只用框架与已有工件：

| 能力 | 来源 |
|---|---|
| `HttpURLConnection` / `URL` | JDK（Android 框架自带） |
| `org.json.JSONObject` / `JSONArray` | Android 框架自带，**不是** 第三方 org.json 依赖 |
| `FileProvider` | `androidx.core:core-ktx`（已在依赖里） |
| `mutableStateListOf` / `SnapshotStateList` | `androidx.compose.runtime` |
| `buildAnnotatedString` / `withStyle` / `withLink` / `LinkAnnotation` / `SelectionContainer` | `androidx.compose.ui:ui` + `androidx.compose.foundation` |
| `NavigationBar(Item)` / `NavigationRail(Item)` / `ModalBottomSheet` / `FilterChip` / `LinearProgressIndicator` | `androidx.compose.material3` |
| `BoxWithConstraints` | `androidx.compose.foundation.layout` |
| `LocalConfiguration` | `androidx.compose.ui.platform` |
| `Dispatchers.IO` / `withContext` / `launch` / `delay` / `Job` | `kotlinx-coroutines`（随 Compose 传递依赖） |

对照参考项目：Kit 那类模板用了 `okhttp` + `commonmark` + `material3-window-size-class`，
本模块刻意全部自实现，宿主少三个依赖、少一次版本对齐。**要换成它们也完全可以**，
接口边界已经收窄在 `AppUpdateChecker.check/download` 与 `MarkdownParser.parse` 两处。

## 3. 需要的 Manifest 与资源改动（只有 U01 需要）

```xml
<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES" />

<application …>
    <provider
        android:name="androidx.core.content.FileProvider"
        android:authorities="${applicationId}.fileprovider"
        android:exported="false"
        android:grantUriPermissions="true">
        <meta-data
            android:name="android.support.FILE_PROVIDER_PATHS"
            android:resource="@xml/file_paths" />
    </provider>
</application>
```

`res/xml/file_paths.xml`：

```xml
<paths>
    <cache-path name="updates" path="updates/" />
</paths>
```

要点：

- `INTERNET` 权限本来就有（示例 App 已声明）；没有的话 U01 请求会直接抛 `SecurityException`。
- `authorities` 必须与代码里的 `"${context.packageName}.fileprovider"` 完全一致，
  改了 Manifest 就要同步改调用处（`AppUpdateChecker.installApk` 的 `authority` 参数可直接传）。
- 只暴露 `cacheDir/updates/`，不要把整个 `cacheDir` 或 `external-path` 开出去。
- 示例 App 的 Manifest 里已经写好这两段，注释里标了「宿主不做自更新就删掉」。

## 4. 权限与隐私

| 条目 | 权限 | 说明 |
|---|---|---|
| U01 | `INTERNET`（已有）、`REQUEST_INSTALL_PACKAGES` | 后者是普通权限，安装时由系统弹窗确认；Android 8+ 还需用户在设置里授予「安装未知应用」，代码已检查并引导 |
| U02 | 无 | 只存内存，不落盘 → 不需要任何存储权限；分享走系统选择器 |
| U03 | 无 | 点链接走 `LocalUriHandler`（浏览器），不需要额外权限 |
| U04 | 无 | 纯布局 |

隐私红线：日志里不许出现 token、密码、带 query 的完整 URL、手机号。
U01 的失败文案里会带异常类名与 message，注意别把带凭据的 URL 打进去
（本实现请求的是固定 API 地址，不含凭据；换成自己的后端时要检查这一点）。

## 5. 线程与生命周期

- `AppUpdateChecker.check()` / `download()` 都是 `suspend` 且内部是阻塞 IO，
  **必须**在 `withContext(Dispatchers.IO)` 里调用；在主线程直接调会抛 `NetworkOnMainThreadException`。
- 下载进度回调来自 IO 线程，写 Compose 快照状态是线程安全的，可以直接赋值。
- 取消下载用 `job.cancel()`；`download()` 内部会在协程取消时中断读取，
  但 `.part` 文件不会自动清理（下次下载会覆盖），介意就自己加 `try/finally` 删文件。
- `AppLog` 是进程级单例，进程被杀即清空——这是**有意的设计**（不留痕、不需权限），
  需要跨重启留存时用 `AppLog.persist` 钩子写 `getExternalFilesDir(null)`，
  自己处理轮转与体积上限（建议单文件 ≤2MB、保留 ≤3 个）。

## 6. 已知平台差异与限制

- **GitHub API 限流**：未带 token 时 60 次/小时/IP，超了返回 403。失败文案已写明这一点。
  私有仓库或想提额度就给 `check(token = …)` 传值，**但 token 绝不能硬编码进客户端**。
- **Release 必须有 APK 附件**：`assets` 里没有 `.apk`（或名字不含 release）时，
  结果仍是 UPDATE_AVAILABLE 但 `apkUrl == null`，界面不显示下载按钮——这是有意的，
  避免给用户一个点了没反应的按钮。本仓库的 release workflow 会同时上传 APK 与源码 zip。
- **`Content-Length` 缺失**：GitHub 的 `browser_download_url` 会 302 到 CDN，
  正常会给长度；万一没有（`total <= 0`），进度条自动切成不确定态，文案只显示已下 MB。
- **覆盖安装签名不一致**：CI 用临时 keystore 签名，与本地/上一版签名不同时系统会拒绝覆盖安装，
  需要先卸载。这不是代码 bug，界面会把安装器返回的失败留给用户看到（安装器自己弹提示）。
- **`versionName` 为空**：某些构建（如纯 versionCode 管理）读出来是 null，
  `currentVersionName()` 会回退成 `"unknown"`，此时 `isNewer()` 判定为非最新，
  界面照常显示最新 tag，不会崩。
- **Markdown 不支持表格/图片**：见 `实现方案.md`；需要就扩解析器或引 commonmark。
- **自适应导航未接入 `AppRoot.kt`**：示例 App 有三套底栏变体（玻璃/O神/纯 Material），
  在沙箱里无法验证视觉回归，所以 U04 只交付可复用外壳 + 可操作演示，没有改主壳。
  接入方法见 `实现方案.md` §4 第 5 条。
