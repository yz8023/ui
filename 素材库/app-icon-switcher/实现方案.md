# 应用图标切换 · 实现方案

> 功能点：在应用**内部**让用户选择、切换、修改桌面上的应用图标，
> 选择后立即生效，无需重新安装。

## 1. 功能效果

在 App 的设置页放一个「应用图标」选择区，列出多套图标（如 冰蓝 / 星夜 / 珊瑚），
点击后桌面图标马上变成选中的那一套。效果类似很多国际大厂应用（如 Google 日历、
微信海外版）的"换图标"功能。

## 2. 实现原理

Android 桌面图标对应的是 **Launcher 入口组件**（`intent-filter` 带
`MAIN + LAUNCHER` 的 Activity 或 activity-alias）。因此"换图标"的通用做法是：

1. **准备多套图标资源**（Adaptive Icon / 自适应图标，`mipmap-anydpi-v26`）。
2. **在 Manifest 里声明多个 `<activity-alias>`**，每个 alias 指向同一个真实
   Activity（主界面），但 `android:icon` 指向不同图标；其中只允许**一个** alias
   处于 `enabled=true`（当前生效的图标）。
3. **运行时切换**：调用 `PackageManager.setComponentEnabledSetting()`
   把想用的 alias 启用、其余 alias 全部禁用。Launcher 读到组件启用状态变化后，
   会刷新桌面图标。

核心代码如下（详见 `代码/` 目录）：

```kotlin
val pm = context.packageManager
pm.setComponentEnabledSetting(
    chosen.component,                 // 目标 alias 的 ComponentName
    PackageManager.COMPONENT_ENABLED_STATE_ENABLED,
    PackageManager.DONT_KILL_APP
)
// 其余 alias 依次置为 DISABLED
```

## 3. 两种实现路线对比

| 路线 | 原理 | 兼容性 | 说明 |
|---|---|---|---|
| **A. activity-alias 切换**（本功能采用的方案） | 预埋多个 launcher 别名组件，运行时启用/禁用 | 所有版本（minSdk 任意） | 最通用、最稳定的方案；缺点：每套图标都要在 Manifest 里写一个 alias，图标数量是静态的 |
| **B. `ActivityManager.setApplicationIcon`** | 运行时直接指定图标 drawable | 仅 Android 13+（API 33+），且为 **RESTRICTED API**（受权限门禁保护） | 可以完全动态换图，但非系统应用很难获得授权，不推荐普通应用使用 |

> 结论：对普通应用，选 **方案 A（activity-alias）**。

## 4. 详细步骤

### 步骤 1：准备多套自适应图标

在 `app/src/main/res/` 下为每套图标准备：

- `mipmap-anydpi-v26/ic_launcher_<名称>.xml` —— 自适应图标（背景 + 前景 + 单色）
- `values/colors.xml` 增加对应背景色
- `drawable/ic_launcher_foreground_<名称>.xml` —— 前景矢量图

> 自适应图标要求背景/前景层独立，系统会把它们裁剪成圆形/圆角矩形等形状。
> minSdk 26 的设备都走 `mipmap-anydpi-v26`，不需要兼容旧格式 PNG。

### 步骤 2：在 Manifest 中声明入口与各 alias

真实主界面 `MainActivity` **去掉** launcher 的 `intent-filter`；默认图标用一个
`enabled="true"` 的 alias 承担 Launcher 入口，其余图标各一个 `enabled="false"`
的 alias：

```xml
<!-- 真实主界面（无 launcher intent-filter，只做 targetActivity） -->
<activity android:name=".MainActivity" android:exported="false" />

<!-- 默认图标：唯一启用的 launcher 入口 -->
<activity-alias
    android:name=".icon.Default"
    android:enabled="true"
    android:exported="true"
    android:icon="@mipmap/ic_launcher"
    android:roundIcon="@mipmap/ic_launcher_round"
    android:targetActivity=".MainActivity">
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
</activity-alias>

<!-- 备选图标：默认禁用，运行时启用 -->
<activity-alias
    android:name=".icon.Galaxy"
    android:enabled="false"
    android:exported="true"
    android:icon="@mipmap/ic_launcher_galaxy"
    android:roundIcon="@mipmap/ic_launcher_galaxy"
    android:targetActivity=".MainActivity">
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
</activity-alias>
```

要点：

- `android:exported="true"` 是 API 31+ 对含 LAUNCHER 的组件的强制要求。
- alias 的 `android:name` 必须是合法的组件名（不能用纯数字开头），习惯用
  `.icon.<名称>` 这种包内二级命名空间。
- 同一个应用只能有一个 `enabled=true` 的 launcher 组件，否则桌面会出现多个图标。

### 步骤 3：运行时切换（核心代码）

用一个 `AppIconSwitcher` 对象统一管理：列出全部图标选项、切换、读取当前图标。

```kotlin
object AppIconSwitcher {
    data class IconOption(
        val key: String,        // 唯一标识
        val label: String,      // 显示名
        val component: ComponentName, // 该图标的 alias 组件
        val previewRes: Int     // 设置页预览用的图标资源
    )

    fun all(): List<IconOption> = listOf(...)

    fun apply(context: Context, target: IconOption) {
        val pm = context.packageManager
        all().forEach { option ->
            val state = if (option.key == target.key)
                PackageManager.COMPONENT_ENABLED_STATE_ENABLED
            else
                PackageManager.COMPONENT_ENABLED_STATE_DISABLED
            pm.setComponentEnabledSetting(option.component, state, PackageManager.DONT_KILL_APP)
        }
    }

    fun current(context: Context): IconOption =
        all().firstOrNull {
            context.packageManager.getComponentEnabledSetting(it.component) ==
                PackageManager.COMPONENT_ENABLED_STATE_ENABLED
        } ?: all().first()
}
```

> `setComponentEnabledSetting` 是异步生效的，桌面 Launcher 需要短暂刷新；
> 个别桌面可能要求重启 Launcher 或稍等几秒才看到新图标，这是系统机制，不是 bug。

### 步骤 4：写一个设置页选择 UI

在设置页放一排图标预览，选中项高亮（示例见 `代码/AppIconSwitcher.kt` 里的
`AppIconPicker` Composable）。

## 5. 常见问题

| 问题 | 原因 / 处理 |
|---|---|
| 换了图标但桌面没变 | Launcher 缓存。等待几秒或重新打开应用/桌面；个别桌面需重启 |
| 出现两个相同图标 | 有超过一个 launcher 组件处于 enabled，检查 alias 的 enabled 互斥逻辑 |
| 切换后应用被杀 | 正常，`DONT_KILL_APP` 只是尽量不杀，个别厂商会强制重启进程 |
| API 31+ 报 `exported` 错误 | 所有含 LAUNCHER 的 alias 必须 `android:exported="true"` |
| 想加更多图标 | 复制一套图标资源 + 一个 alias + 一个 IconOption，三处各加一份即可 |
