## 路线 B（选了近似时）的命名与交付规矩

- 交付物必须命名为「磨砂玻璃（View 近似）」，禁止叫「液态玻璃」或写「已对齐 ui 模板」；
- 参数可以借鉴模板的圆角/透明度/高光取值，但汇报里要专列一节「与模板真玻璃的差异」，
  至少写清：无 backdrop 实时采样、无 lens 折射、滚动经过下方的内容不会被折射；
- 近似实现优先用系统能力：API 31+ 背景模糊（`Window.setBackgroundBlurRadius` /
  `RenderEffect.createBlurEffect`）或截图降采样模糊，禁止为一条底栏引入整套 Compose；
- 验收不看「像不像截图」，看：滑动时不掉帧、深浅色都可读、所有原本可点的区域仍可点
  （尤其底栏第一个/最后一个标签——历史上曾因坐标钳位导致首页点不到）。

## 路线 A（选了迁 Compose 时）

- 只迁要用玻璃的那几个页面，用 `ComposeView` 嵌入现有 Activity/Fragment，不要一上来重写全 App；
- 工具链成本先讲明：引入 Kotlin 2.3.10 + Compose 插件与 BOM、compileSdk 36、APK 体积与构建时长增加；
- 玻璃根部接线（双层 backdrop 录制）要在被迁页面的 Compose 树内自洽，
  页面外的 View 内容录不进 Compose 图层，采样范围仅限 Compose 内的背景层——先拿一个页面验证再扩。

## 任何情况下都不许做的事

- 不许把 Compose 的 `LiquidBottomTabs.kt` 逐行「翻译」成 Java 自定义 View 后声称 1:1 对齐；
- 不许一版里同时推进两条路线（试错代码要隔离，不要合进主线）；
- 效果达不到就如实写进「未做到/降级项」，不许用调参数把「不像」磨成「差不多就算了」。
