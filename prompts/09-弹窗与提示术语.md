# 弹窗与提示术语提示词（F17 / P01–P12）

> 用法：跟 AI 说「加个弹窗」之前，先把这条发过去——它会知道你说的是 Alert 还是 Toast，
> 以及你要的是 Web 还是 Android。每条提示词都在 App 详情页可**长按复制**。
> 术语数据与实现的唯一权威源码：`android/…/ui/features/overlayterms/OverlayTermsSpec.kt`。
> 来源与口径：`素材库/弹窗与提示术语/参考来源.md`。

## 0. 先选对术语，再谈实现（强度排序 + 选型四问）

```text
强度从高到低：Alert（必须点掉）> Modal（在里面做完一件事）> Drawer / BottomSheet（边缘面板）
> Popconfirm / Popover（锚定气泡）> Snackbar（可撤销条幅）> Toast（自动消失）；
Loading 是过程反馈、Badge 是持续状态，两者不弹但同属提示族。

选型四问：
1. 要不要打断用户当前的操作？
2. 打断完要不要用户在里面做事（输入/选择/确认）？
3. 这件事发生在哪个元素旁边（需要锚定吗）？
4. 错过这条信息会不会有损失（会 → 不能用 Toast；能撤销 → 优先 Snackbar）？

回答完这四问再选术语，不要笼统说「弹窗」。
```

## 1. P01 Alert 警告框

```text
帮我实现一个 Alert（警告框 / 告知框）：模态、阻塞，用来告知一个用户必须知道的结论，
只有一个「知道了」类确认按钮，不需要用户做选择或输入。
关键要求：内容不超过 3 行；标题一句话说清发生了什么；正文说清影响；
按钮文案用结果导向动词（如「继续下载」而不是「确定」）；
明确它能否被点遮罩/返回键关掉——不可绕过的 Alert 要挡住这两种关闭方式。
Web：语义化 <div role="alertdialog" aria-modal="true">，焦点进框、Esc 行为按可否绕过决定；
Android/Compose：AlertDialog，只给 confirmButton，不给 dismissButton；
用 DialogProperties(dismissOnBackPress, dismissOnClickOutside) 控制可否绕过。
不要用 Alert 承载需要输入或选择的场景（那是 Modal）。
自检：能不能不点按钮就关掉？关掉后用户是否仍然知道发生了什么？
```

## 2. P02 Toast 轻提示

```text
帮我实现一个 Toast（轻提示）：不阻塞、自动消失、不可交互，用来确认一个已经完成的动作。
关键要求：出现 1.5–3.5 秒后自动消失；不遮挡主要操作区；
同一时间只保留一条（新的替换旧的，不要排队叠一摞）；不放需要用户处理的信息。
Web：自绘 div，绝对定位在视口底部或顶部，配 transition 与定时器，aria-live="polite"；
Android/Compose：系统 Toast.makeText(context, text, duration).show()（样式受限、后台不显示），
需要品牌样式就自绘一个 Composable，用 LaunchedEffect + delay 控制消失。
关键信息（比如操作失败、可撤销）不要放 Toast——用 Snackbar 或 Alert。
自检：连续点五次，会不会出现五个提示叠在一起？消失后用户是否还能知道结果？
```

## 3. P03 Modal 模态框

```text
帮我实现一个 Modal（模态框 / 对话框）：遮罩 + 居中面板，用户必须在里面完成一件事才能离开。
关键要求：遮罩挡住背景交互；面板内是完整任务（标题 + 表单/说明 + 主次按钮）；
主按钮在条件不满足时禁用而不是弹错误；打开时焦点落在第一个可交互元素；
关闭时把输入内容或结果回传给调用方；移动端键盘弹起要给 imePadding，别让按钮被顶出屏幕。
Web：<dialog> 或自绘遮罩层，处理 focus trap 与 Esc；
Android/Compose：androidx.compose.ui.window.Dialog + DialogProperties，
面板用 Surface，输入用 OutlinedTextField，外层 Modifier.imePadding()。
只告知结论不需要用户操作的场景用 Alert，不要用 Modal 承载一句话提示。
自检：点遮罩、按返回键分别是什么行为？键盘弹起后按钮还在屏幕内吗？
```

## 4. P04 Drawer 抽屉

```text
帮我实现一个 Drawer（抽屉 / 侧边栏）：从屏幕边缘滑出的面板，装导航或一批相关内容。
关键要求：滑出方向明确（移动端多为左或右，桌面端左侧常见）；
面板外有半透明遮罩（scrim），点遮罩或返回键关闭；
动画用位移 + 遮罩透明度同步，时长 200–300ms；
面板宽度不超过屏幕 80%，内容可滚动；选中项要有明确高亮并回显。
Web：position: fixed 面板 + transform: translateX() 过渡 + 遮罩层；
Android/Compose：可用 ModalNavigationDrawer，或自绘 Box + animateFloatAsState(tween(260)) +
Modifier.offset { IntOffset(((progress - 1f) * widthPx).roundToInt(), 0) } + scrim +
BackHandler(enabled = open)（自绘版可控性更好，也方便做手势滑开）。
装的是「一批要选的项」或「就地小任务」时，用 BottomSheet / Popover，不要用 Drawer。
自检：遮罩透明度和面板位移是否同步？返回键能否关闭？关闭后再开状态是否正确？
```

## 5. P05 Popconfirm 气泡确认框

```text
帮我实现一个 Popconfirm（气泡确认框）：贴着触发按钮弹出的小气泡，做就地二次确认。
关键要求：气泡锚定在触发元素旁，空间不足时自动翻转到另一侧；
内含一句短问话 + 取消/确认两个按钮，确认按钮用危险色；
点气泡外或返回键关闭；破坏性操作确认后要给「撤销」而不是再弹一个 Alert；
不要用 Popconfirm 承载表单或长说明（那是 Popover 或 Modal）。
Web：绝对定位气泡 + 计算触发元素 rect，箭头指向触发元素；
Android/Compose：DropdownMenu(expanded, onDismissRequest)（自动锚定 + 边缘翻转），
菜单内放 Text 问话 + Row(取消/删除)；删除后在 Snackbar 里给「撤销」，
恢复时把条目放回**原下标**（用 list.toMutableList().apply { add(index, item) }）。
危险操作只有「不可撤销」时才升级为 Modal 确认。
自检：撤销后条目是否回到原位置？气泡会不会被屏幕边缘切掉？
```

## 6. P06 Tooltip 文字提示

```text
帮我实现一个 Tooltip（文字提示）：指向某个图标或按钮的纯文字注解，解释它是干什么的。
关键要求：只放一两行文字，不放按钮和链接；
桌面端 hover 延迟 300–500ms 出现、移开即消失，移动端用长按触发；
不遮挡被解释的元素；多个 Tooltip 同时只出现一个；
图标必须另有 contentDescription/aria-label，不能只靠 Tooltip 传递信息。
Web：绝对定位小气泡 + role="tooltip"，由 aria-describedby 关联；
Android/Compose：Modifier.combinedClickable(onLongClick = …) 触发一个只含 Text 的
DropdownMenu，再用 LaunchedEffect(key) + delay(1800) 自动关闭（需
@OptIn(ExperimentalFoundationApi::class)）；Material3 的 TooltipBox 是实验 API，
要抄进生产项目建议用上面这套稳定写法。
需要用户在里面点东西的场景用 Popover，不要用 Tooltip。
自检：连续长按三个不同图标，提示会不会串？无障碍服务能否读到同样的信息？
```

## 7. P07 Snackbar 条幅提示

```text
帮我实现一个 Snackbar（条幅提示）：屏幕底部（或桌面端左下角）的一条横条幅，
告知结果，并可选地给一个「撤销」动作。
关键要求：自动消失（短 4 秒 / 长 10 秒），带撤销动作时用短的；
最多一个动作按钮，不要放两个；同一时间只显示一条；
用户可主动划走；不阻塞背景交互；撤销必须真的把状态恢复回去。
Web：底部固定条幅 + 定时器 + 一个 action 按钮；
Android/Compose：Scaffold 的 snackbarHost = SnackbarHost(state)，
scope.launch { val r = state.showSnackbar(message, actionLabel = "撤销", duration = Short) }，
在 r == SnackbarResult.ActionPerformed 时恢复数据（showSnackbar 是挂起函数，
它返回时才知道用户是点了动作还是自然消失）。
需要用户必须看到的结论用 Alert；只是确认动作完成、错过也无所谓用 Toast。
自检：点撤销后数据是否恢复？条幅会不会把底部导航挡住？
```

## 8. P08 Notification 系统通知

```text
帮我实现一个 Notification（系统通知）：应用在前台之外、通过系统通知栏触达用户。
关键要求：Android 8+ 必须建 NotificationChannel（id、名称、重要性一次定死，
之后用户可改，代码改不了）；通知小图标必须是纯色透明底（彩色图会糊成白块）；
Android 13+ 要运行时申请 POST_NOTIFICATIONS，未授权时不要静默失败，
要么禁用发送入口并说明，要么引导去设置；点通知要能跳到对应页面（PendingIntent）；
同一类事件用同一 notify id 更新而不是无限堆叠。
Android/Compose：NotificationManager.createNotificationChannel(
NotificationChannel(id, name, IMPORTANCE_DEFAULT)) +
Notification.Builder(context, channelId).setSmallIcon(R.drawable.ic_stat_x)
.setContentTitle(…).setContentText(…).build() + manager.notify(id, n)，
权限用 ContextCompat.checkSelfPermission + rememberLauncherForActivityResult。
Web：Notification API + Service Worker 推送，需用户授权，iOS 需安装到桌面。
应用内可见的反馈不要用系统通知（用 Snackbar / Toast）。
自检：未授权时点发送会怎样？通知栏里的小图标清楚吗？点通知跳对页面了吗？
```

## 9. P09 Popover 气泡卡片

```text
帮我实现一个 Popover（气泡卡片）：锚定在触发元素旁的富内容气泡，里面可以放列表、开关、输入。
关键要求：与 Tooltip 的区别是「能干活」——内容可交互；
锚定触发元素并在空间不足时翻转；点外部、按返回键或选中后关闭；
内容行高 ≥44dp 便于触摸；宽度自适应内容但设上限（移动端不超过屏宽 - 32dp）。
Web：绝对定位容器 + 点击外部关闭（document 监听或 :focus-within）；
Android/Compose：DropdownMenu 内直接放自定义 Column（Row + Icon + Text + Switch +
HorizontalDivider），不必用 DropdownMenuItem；ExposedDropdownMenuBox 的语义是「选择器」，
承载富内容时用裸 DropdownMenu 更合适。
只有一个纯文字解释用 Tooltip；要做破坏性确认用 Popconfirm。
自检：点气泡内部会不会误关？开关状态改了之后气泡外是否同步？
```

## 10. P10 BottomSheet / ActionSheet 底部面板

```text
帮我实现一个 BottomSheet（底部面板）/ ActionSheet（动作面板）：从底部升起的面板，
移动端的首选浮层，因为拇指可达、不打断阅读上下文。
关键要求：支持半展开与全展开两档（内容少就只做一档）；
顶部有拖拽把手（grabber）；下滑或点遮罩关闭；关闭要有下滑动画而不是瞬间消失；
装「一组可选动作」时是 ActionSheet：标题（可选）+ 动作列表 + 取消，
破坏性动作用危险色并单独分组；内容可滚动时面板高度设上限。
Web：底部固定面板 + transform: translateY() 过渡 + 遮罩 + touch 手势；
Android/Compose：ModalBottomSheet(onDismissRequest, sheetState =
rememberModalBottomSheetState(skipPartiallyExpanded = false))，
关闭要 scope.launch { sheetState.hide() } 再置 false 才有动画
（需 @OptIn(ExperimentalMaterial3Api::class)）；半屏非模态用 ModalNavigationDrawer 之外的
BottomSheetScaffold。
桌面端宽屏时改用 Popover 或 DropdownMenu，底部面板在大屏上会显得很怪。
自检：下滑能关吗？关闭有动画吗？列表长了会不会顶出屏幕？
```

## 11. P11 Loading / Progress 加载与进度

```text
帮我实现三档加载反馈，并说清什么时候用哪档：
1) 非阻塞进度条（LinearProgressIndicator / 顶部细线）：后台在跑，用户可以继续操作；
2) 按钮内加载态（按钮里 16dp 圆环 + 文案变「提交中…」）：单次操作，防止重复点击，
   **按钮宽度不能跳**（把文案区宽度固定或先量好）；
3) 全局遮罩加载（半透明遮罩 + 圆环 + 可取消）：整个页面都不能动，
   超过 3 秒必须给取消或说明。
关键要求：超过 300ms 才显示加载态（避免闪烁）；进度可知时用确定进度
（progress = { 0.62f }），未知时用不确定态；失败要有错误态和重试，不要一直转圈；
不要为了「看起来在加载」而人为延迟真实结果。
Web：CSS 动画 + aria-busy="true"，进度条用 role="progressbar" 带 aria-valuenow；
Android/Compose：LinearProgressIndicator(progress = { p })（lambda 形式，BOM 2024.10 起）、
CircularProgressIndicator(Modifier.size(16.dp), strokeWidth = 2.dp)、
Box(Modifier.fillMaxSize().background(scrim).clickable(enabled = false){}) 做遮罩，
推进用 LaunchedEffect(running) + delay；取消按钮要真的中断协程（job.cancel()）。
自检：加载期间背景能不能点？取消之后状态回滚了吗？按钮宽度跳了吗？
```

## 12. P12 Badge / Dot 角标与红点

```text
帮我实现一个 Badge（角标）/ Dot（红点）：附着在图标右上角的持续状态标记。
关键要求：数字角标超过 99 显示「99+」（超过 999 显示「999+」），
数字为 0 时**整个角标不渲染**（不是渲染一个 0）；
红点只表示「有变化」不表示数量；角标字号 10sp 左右、圆形背景（RoundedCornerShape(percent = 50)）
并加 2dp 背景色描边以免和图标糊在一起；数量变化要有轻微缩放动画；
角标不能是唯一的信息载体，列表里也要能看到同样的信息（无障碍）。
Web：绝对定位 span + border-radius: 999px + 背景色描边，aria-label 读出数量；
Android/Compose：Box(contentAlignment = TopEnd) 里叠一个
Surface(shape = RoundedCornerShape(percent = 50), color = MaterialTheme.colorScheme.error) +
Text(count.toString(), color = onError)，红点用 CircleShape + 9dp；
底部导航项可用 NavigationBarItem 的 badge 参数（M3 1.2+）。
临时告知用 Toast/Snackbar，持续状态才用 Badge。
自检：count = 0 时角标还在吗？count = 100 显示什么？深色模式下描边够吗？
```

## 13. 抄进宿主时的通用要求（发给 AI 的收尾段）

```text
约束（与仓库 AGENTS.md 一致）：
- 演示必须真实可操作：真 Toast / 真 AlertDialog / 真 DropdownMenu / 真 SnackbarHost /
  真 NotificationManager / 真 ModalBottomSheet。不许用截图、静态卡片或 Text("这里是弹窗") 冒充。
- 只改 package 与资源引用（如 R.drawable 通知小图标），不改类名与函数名；
  宿主没有 GlassCard / SectionTitle / AppIcons 时，换成 Surface / Text / 自己的图标。
- 目录与详情的列表状态用 rememberSaveable(saver = LazyListState.Saver)，
  选中态存 id 字符串，保证「返回不回顶部」。
- P08 未授权时不许静默失败：禁用发送按钮并给申请入口。
- 改完跑 scripts/check-template.py（素材库镜像不许漂移），并逐条过验收清单。
```
