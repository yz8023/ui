# 通用开工提示词（任何功能都先发这条）

```
你要把模板仓库 https://github.com/yz8023/ui 的功能接入我的项目。开始前必须遵守：

1. 先完整阅读该仓库根目录的 AGENTS.md、docs/00-新人入口-先读这个.md，
   以及 docs/功能逐项手册.md 中本次功能的那一节。读完前不要写任何代码。
2. 我要的功能是：【填写功能编号，如 F01 / F03，不要只写功能名】
   我的项目情况：【语言 Java/Kotlin；UI 体系 View/Compose；compileSdk；minSdk；
   是否已有 Kotlin 与 Compose 插件；Gradle/AGP/Kotlin 版本】
3. 先回复一张开工表：功能编号 / 我的技术栈体检结论 / 选定路线（A 整壳 / B Compose 单功能 /
   C View 替代实现 / D 不适配需停工）及理由 / 将新增与修改的文件逐个清单 /
   明确不做的事项。等我确认后再动手。
4. 硬性禁止：
   - 禁止重命名模板里的类、函数、文件（只许改 package 和 R 引用）；
   - 禁止把核心机制换成你认为"差不多"的实现；做不到原机制时停下来报告，不要近似冒充；
   - 禁止混用同一功能的另一套变体（手册里标注了哪套是唯一权威、哪套已合并）；
   - 禁止跳过前置功能、禁止删调用/写空实现来绕过编译错误；
   - 禁止顺手升级依赖版本、重构无关文件；
   - 禁止把任何 Token/密钥写进代码、文档或 git remote。
5. 实施方式：整文件复制权威源码后做最小修改；编译报错先查手册对应章节的"失败指纹表"，
   表里没有的错误把完整报错发我，不要连续盲改超过 3 轮。
6. 完成后按这个格式汇报，缺一项视为未完成：
   - 功能与路线；新增文件（逐个，注明来源路径和只改了哪里）；修改文件（逐个，改了什么）
   - 编译：完整命令 + 结果输出摘录
   - 验收：手册验收清单逐项结果；涉及真机效果的写明机型/现象/等待时间或 adb 输出
   - 未做到与降级项（没有写"无"）；与模板的差异（没有写"无"）
```
